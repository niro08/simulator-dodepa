# Backlog задач от Creative Director — итерация «Роглайт + Витрина/Изнанка»

> Источник: `design/creative-vision.md` (далее **CV**) и `design/market-research.md`.
>
> **Приоритеты:**
> - **P0** — делаем в этой итерации. Только Vue 3 + TS + Pinia + Vite, без внешних ассетов: эмодзи, CSS, инлайн-SVG, Web Audio. Единственная допустимая новая dev-зависимость — `vitest`.
> - **P1** — следующая итерация, до Steam-демо.
> - **P2** — после релиза или по возможности.
>
> **Общие правила для всех задач:**
> - игровые числа живут только в `src/game/balance.ts`, тексты — в `src/game/content/`;
> - в компонентах нет игровой логики;
> - `npm run type-check` и `npm run build-only` проходят;
> - этические анти-пиллары (CV §3) не нарушаются.

### CD-01 · GDD «Структура рана» · `game-designer` · P0
- **Цель.** Превратить CV §5–6 в спецификацию, по которой можно писать код.
  - Машина состояний: Меню → Ран (Утро → День → Сон) → Счета → Концовка → Выписка → Меню.
  - Порядок операций при сне и утром: проценты, вывод, события, счета, проверки концовок.
  - Обучение в первые 2 дня (подсказки вместо HowToPlay).
- **Критерии приёмки.**
  - Есть файл `design/gdd/run-loop.md` с диаграммой состояний.
  - Для каждого действия таблица: стоимость ⚡, эффекты, условия недоступности, текст ошибки.
  - Точный порядок тиков Сна и Утра.
  - Условия всех 7 концовок и приоритет, если сработали две сразу.
  - Описаны 3 edge-case: отрицательный кошелёк после штрафа, вывод в день счетов, тильт 100 во время бонуса.
  - Сценарий первых 3 минут игры (что видит и нажимает игрок).
- **Зависимости:** нет.

### CD-02 · Экономика v1 и симуляция · `economy-designer` · P0
- **Цель.** Утвердить числа из CV §6.2–6.3 и оформить их в спецификацию `src/game/balance.ts`.
- **Критерии приёмки.**
  - Есть файл `design/balance/economy-v1.md`.
  - Полная таблица констант: имя, значение, обоснование.
  - Таблица выплат слота с формулой RTP. RTP = 0.90 ± 0.005, частота «выигрышей» 30–35%.
  - Результаты симуляции ≥ 10 000 ранов по стратегиям:
    - «честный без ломбарда» — 50–65% побед;
    - «честный с ломбардом» — ≥ 90%, но теряет в среднем ≥ 2 вещей;
    - «казино каждый день, ставка 100, без ломбарда» — ≤ 15%;
    - «темка каждый день» — ≤ 20% побед;
    - «бонус 200%» — отыгрыш ≤ 15%.
  - Расчёт медианной длины рана в действиях (цель: 25–40 мин при ~1 мин/день).
  - Подтверждено, что никакой мета-анлок не меняет RTP.
- **Зависимости:** CD-01.

  - Короткая спецификация звуков: `design/audio/sfx-spec.md`.
- **Зависимости:** CD-07 (ui-programmer помогает с интеграцией).

### CD-21 · Доступность и фотобезопасность · `accessibility-specialist` · P0
- **Цель.** Неон не должен вредить (эпилепсия, мигрени).
- **Критерии приёмки.**
  - Аудит CD-16 и CD-18: ни один элемент не мигает > 3 Гц.
  - Настройка «Меньше мигания» включена по умолчанию, если `prefers-reduced-motion`.
  - Контраст текста ≥ 4.5:1.
  - Все действия доступны с клавиатуры, фокус видим.
  - Эмодзи-кнопки имеют `aria-label`. Тикеры помечены `aria-hidden` или имеют паузу.
  - Отчёт: `design/accessibility/audit-p0.md` с найденными проблемами и фиксами (фиксы вносит ui-programmer).
- **Зависимости:** CD-16, CD-18.

### CD-22 · Приёмочное тестирование итерации · `qa-tester` · P0
- **Цель.** Проверить, что итерация играбельна и соответствует CV.
- **Критерии приёмки.**
  - Чеклист `production/qa/p0-checklist.md`.
  - 5 полных ранов разными стратегиями, достигнуты ≥ 5 из 7 концовок (остальные — через debug-seed).
  - Мобильная версия на 360px.
  - Миграция старого сейва.
  - Отсутствие реальных брендов в текстах (grep по списку).
  - Проверка анти-пилларов: нет кнопок оплаты, нет наград за ежедневный вход.
  - `type-check`, `build-only` и `test` зелёные.
  - Баг-репорты с шагами воспроизведения.
- **Зависимости:** все P0.
