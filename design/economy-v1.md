## 1. Принципы и целевые метрики

- **Слот честно нечестный.** RTP 0.90 — константа конфига. На него не влияют тильт, мета-анлоки, скины, ставка, день и бонус (§12).
- **Главная цена казино — время (⚡), а не проценты.** У «казино каждый день» прямой проигрыш в слоте за ран ≈ 3 450₽. Остальное он теряет потому, что 40⚡ в день уходят на спины вместо «Помочь семье»: без роста ❤️ нет бонуса +30% к смене: смена в среднем 1 122₽ против 1 428₽ у честного (≈ −8 500₽ за 28 смен). Эту разницу видно в Изнанке.
- **Честный путь — «впритык».** Запас к каждому счёту ≈ +1 100₽ (медиана), и его съедает одна бытовая карточка. Решения вокруг спина (пиллар 2) — ломбард, МФО, друзья, темка, отсрочка.
- **У каждого короткого пути длинная цена** (пиллар 3): ломбард → оценка B/C; друзья → ❤️ и блокировка; МФО → 1%/день и «Минимализм»; темка → ❤️, штраф, «Сел».

### 2.2 Таблица выплат (правила по приоритету, срабатывает первое)

`w` — число комбинаций из 90³ = 729 000. Вероятность `p = w / 729 000`.

**Формула RTP (аналитически):**
`RTP = Σ_i p_i × x_i = (100·729 + 25·2744 + 20·5832 + 10·17417 + 5·64 + 1·64 + 2·59616 + 1·51504 + 2·4128 + 0.5·88752) / 729000 = 656062 / 729000 = 0.899948`.
В общем виде `p_i = Σ_{(a,b,c) ∈ правило i} w_a·w_b·w_c / N³`. Функция `expectedRtp(slot)` перебирает 8³ = 512 комбинаций символов, и тест сравнивает результат с `656062/729000` точно. Контроль Монте-Карло: 10⁶ спинов дают 0.9032 (σ среднего 0.0042).

| Производная метрика | Значение | Где используется |
|---|---|---|
| Hit (выплата > 0, «Витрина празднует») | 31.67% | ачивки, Изнанка |
| LDW (0 < x < 1) | 12.17% | CV: «~12%» ✓ |
| Push (x = 1) | 7.07% | Изнанка: «ВЫИГРЫШ = твоя же ставка» |
| **P_REAL_WIN** (x > 1) | **12.42%** | серый тикер: `round(0.8758/0.1242)` = **7** проигрышей на 1 победу |
| P_LOSS_LIKE (x < 1) | 80.51% | тильт |
| P(x ≥ 2) | 12.42% | тильт |
| Дисперсия множителя σ² | 17.58 (σ = 4.19 ставки) | формула бонуса §5.4 |
| P(≥1 джекпот за ран) | 1 − 0.999ⁿ: при ~350 спинах за ран ≈ 30% | тикер/ачивка «Три топора» |

**Округление:** `payout = floor(bet × x)`. Дробный только множитель 0.5. При нечётной ставке игрок теряет 0.5₽ на LDW, это до −0.12 п.п. RTP при ставке 51. Предлагаю новый ключ `BET_STEP = 10`: кнопки ½/×2 и ввод округляют ставку вниз до кратного 10. «ДОДЕП ВСЁ» ставит ровно `casino` (редкий случай, допустимо).

**Near-miss (визуал, CV):** в 25% исходов `lose` (`NEAR_MISS_SHARE = 0.25`) раскладка заменяется на 7️⃣7️⃣X в случайном порядке, где X ∈ {🍋, 🍊, 🍉, 🤡}. Такая раскладка по таблице — всегда `lose`: 7-7-⭐ дал бы `premium_mix`, 7-7-🍒 дал бы LDW, поэтому ⭐💎🍒 в X запрещены. Тест: раскладка near-miss проходит через `evalReels` и даёт `lose`.

**Реализация исхода (рекомендация, совместимо с ADR-001):** брать три символа с барабанов (`rng` × 3 по весам) и прогонять через `evalReels`. Раскладка тогда честная, а распределение исходов по построению совпадает с таблицей `outcomes` (§14.2). Таблица `outcomes` с весами w нужна для `expectedRtp`, Изнанки и тестов. Выбирать исход по весу, а потом подбирать символы — эквивалентно, но требует генератора раскладки под каждый `outcomeId`.

### 2.3 Почему такая таблица
- LDW 12% и hit 31.7% — из CV. Реальных побед 12.4% — это та самая «кричащая» разница между Витриной (31.7%) и Изнанкой (12.4%).
- Ступени 0.5 / 1 / 2 / 10 / 20 / 25 / 100 дают частые мелкие «праздники» и редкие крупные. Джекпот ровно 1:1000 — число, которое легко объяснить.
- Слот нельзя «выучить»: барабаны независимы, у ставки нет модификаторов, ни одна кнопка ничего не удерживает.

### 5.4 Формула ожидаемого остатка после отыгрыша (для Изнанки, CD-06/CD-17)

Баланс казино при серии ставок `b` — случайное блуждание с поглощением в 0. Диффузионное приближение:

```
n   = W / b                         // W = wagerReq − wagered (оставшийся оборот), b = min(bet, BONUS_MAX_BET)
μ   = −(1 − RTP) · b                // дрейф за спин  (−10 при b = 100)
σ²  = VAR · b²                      // VAR = 17.58 (дисперсия множителя, §2.2)
m   = C + μ·n ;  m' = −C + μ·n ;  s = σ·√n ;  k = exp(−2·μ·C / σ²)      // C = текущий casino
E[остаток] = max(0, [m·Φ(m/s) + s·φ(m/s)] − k·[m'·Φ(m'/s) + s·φ(m'/s)])
P(отыграю) = Φ(m/s) − k·Φ(m'/s)
```
`Φ`/`φ` — CDF/PDF стандартного нормального распределения (`erf` — аппроксимация Абрамовица–Стиган 7.1.26, 5 строк). Сверено с Монте-Карло (§5.3): погрешность ≤ 10% отн. — для текста Изнанки достаточно. Референс-реализация: `expectedBonusLeft()` в `tools/balance-sim/sim.mjs`.
Строка для UI рядом: «ожидаемая потеря на обороте = 10% × W». Заглушка GDD `max(0, casino − 0.1·W)` даёт 0 почти всегда и занижает остаток. Заменить на формулу выше.

## 10. Ограничения и инварианты (закрывают B-05, B-06)

**B-05 (отрицательные и неограниченные награды):**
- Формула `calculateReward` с `guaranteed = 0.6 + rep/300` **удаляется**. Все награды — фиксированные таблицы с жёсткими границами: смена ∈ [630; 2048], темка-успех ∈ [1800; 2800], друзья ∈ {0} ∪ [50; 800], займы фиксированы. Ни одна награда не бывает < 0: отрицательные исходы (штраф темки, недостача) — отдельные списания через `forcedPay`.
- ❤️ ∈ [−15; 40] **после каждой команды** (`applyInvariants`), а не только при загрузке (закрывает B-07).

**B-06 (бесконечный цикл денег):**
- У каждого исхода слота `energyDelta = 0`: проигрыш больше не даёт ⚡.
- ⚡ приходит только утром (`energy = 100 + energyModNextMorning`, без накопления). Внутри дня ⚡ не растёт. Исключение — `dream_777 b` (+10, кламп 100, раз в 7 дней).
- Спины при 🔥 ≥ 70 стоят 0⚡, но каждый спин стоит денег (EV −10% ставки) и поднимает тильт, ведя к «Ночи» (−20% баланса, конец дня).
- **Порог для регресс-теста ARCH ADR-009 п.4:** цикл «все ⚡ на спины по 50 → темка», 1000 ранов с seed, 28 дней. Средний прирост `wallet + casino − debt` за день ≤ +150₽ (EV одной темки) — против +516₽/цикл в B-06. И при 10⁴ случайных командах `energy` ни разу не превышает 100 и не растёт внутри дня (кроме `dream_777`).

**Клампы и потолки (сводка):** все деньги — целые, ≥ 0; `payout = floor`, всё, что платит игрок, — `ceil`; ставка ∈ [50; casino], ≤ 100 при активном бонусе, шаг 10; `debt + LOAN ≤ 30 000` для новых займов; 🔥 ∈ [0; 100] (не от спина ≤ 99); бонус ≤ 10 000; кап вывода отсутствует (одноразовая комиссия 5%).

## 12. Мета-анлоки не меняют RTP

- `slot` (барабаны, таблица) и `balance` — константы `GameConfig`. `Profile`, ачивки и косметика туда не входят и в `resolveSpin` не передаются (SD §2.6).
- Скин меняет только отображение `SymbolId → ассет`. Набор из 8 `SymbolId` и веса общие для всех скинов (тест ARCH: скин покрывает все символы).
- P1-предыстории могут менять только `START_*` (кошелёк, ❤️, вещи), но никогда `SLOT`, `BONUS_*`, `TILT_*`. Правило для CD-31: предыстория = патч `START_*` + текст.
- Тест: `expectedRtp(config.slot) === 656062/729000` для `defaultConfig` и для конфига после применения любой косметики/предыстории. Плюс grep: `src/game/progression.ts` и `config/cosmetics.ts` не импортируют `config/slot.ts`.

## 13. Открытые вопросы (кому решать)

1. **[CD]** Критерий «честный с ломбардом теряет ≥ 2 вещей» → «≥ 1 вещь в ранах с ломбардом» (§11.3).
2. **[systems-designer]** Принять переопределение тильта (§7). В SD §2.8 заменить E[Δ] 5.9 → 2.6, «0→100 ≈ 17» → «≈ 38 за сессию», пропорцию тикера 1:6 → 1:7.
3. **[GD]** Новые ключи `BONUS_MAX_BET`, `BET_STEP`, `NEAR_MISS_SHARE`, `FREESPIN_BET` и бытовые карточки `life_*` добавить в §7 GDD. В §3.5.4 ставка клампится ещё и `BONUS_MAX_BET`.
4. **[writer]** Тексты с числами: «×30» → «×40»; «+макс. ставка 100₽*»; «9 проигрышей на выигрыш» → 7; «~11% отыгрывают» → «~8%»; «66.6%» → 68.3% чистых проигрышей / 80.5% «проигрыш или LDW»; «Смена = 900₽» остаётся. Плюс 3 карточки `life_*`.
5. **[producer]** Время казино-игрока 43 мин — верх коридора. Если плейтест покажет > 40, сократить длительность анимации спина (1.2 → 0.9 с) или сделать быстрые ставки. Экономику это не трогает.

export function evalReels(r: Reels, rules: readonly PayRule[] = SLOT_V1.paytable): PayRule {
  for (const p of rules) {
    switch (p.kind) {
      case 'triple': if (r[0] === p.symbol && r[1] === p.symbol && r[2] === p.symbol) return p; break
      case 'triple_any': if (r[0] === r[1] && r[1] === r[2] && p.of.includes(r[0])) return p; break
      case 'all_in': if (r.every((s) => p.of.includes(s))) return p; break
      case 'count': if (r.filter((s) => s === p.symbol).length === p.count) return p; break
      case 'else': return p
    }
  }
  throw new Error('paytable without else')
}

/** Точный RTP перебором 8³ комбинаций. Тест: === 656062/729000. Не принимает состояние — тильт/мета не могут влиять. */
export function expectedRtp(slot: SlotConfigV1 = SLOT_V1): number {
  const w = slot.symbols.map((s) => slot.reelWeights[s]); const N = w.reduce((a, b) => a + b, 0)
  let acc = 0
  for (let a = 0; a < w.length; a++) for (let b = 0; b < w.length; b++) for (let c = 0; c < w.length; c++)
    acc += w[a] * w[b] * w[c] * evalReels([slot.symbols[a], slot.symbols[b], slot.symbols[c]], slot.paytable).mult
  return acc / N ** 3
}

### 14.4 Тесты баланса (дополняют ARCH ADR-009)
1. `expectedRtp(SLOT_V1) === 656062/729000`. Сумма `outcomes[].weight` = 729 000, и каждый `weight` равен перебору.
2. Монте-Карло 10⁵ спинов с seed: RTP ∈ [0.88; 0.92], LDW ∈ [11.5%; 12.9%].
3. Near-miss-раскладка всегда `evalReels → lose`. Раскладка исхода ≠ `lose` никогда не подменяется.
4. Регресс B-05: при ❤️ ∈ [−15; 40] и любых promos `shiftPay ∈ [630; 2048]`, `friendAmt ∈ {0} ∪ [50; 800]`.
5. Регресс B-06 — порог из §10.
6. Порт `tools/balance-sim` в vitest (CD-04): 2000 ранов на стратегию укладываются в коридоры ±5 п.п. от §11.2.
