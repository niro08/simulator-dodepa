# Пакет 2 «Лёгкие деньги кончаются»: темка → контакты

Статус: готово к реализации. 2026-09-29. Источник: core-loop-variety.md §2 п.2, video-soBphAGV63M-summary.md («прокачка удачи», отыгрыш через криминал). Решение Егора: «контакты» вместо кнопки «Темка». Зависит от пакета 1 (quick-fix-evening.md): сделка занимает вечер. «Стример» не трогаем.
Флаг: `FEATURE_CONTACTS` (в `BALANCE_V1`, после релиза `true`). Работает только вместе с `FEATURE_EVENING_FIX`: `contactsOn(B) = B.FEATURE_CONTACTS && B.FEATURE_EVENING_FIX`. При `contactsOn = false` ядро байт-в-байт как сейчас: поле `contacts` не создаётся, подпоток RNG не вызывается, `work/offer` отклоняется `feature_disabled`, `work/shady` работает по-старому.

## 1. Обзор
Каждое утро на вкладке «Работа» лежат 2–3 предложения от конкретных людей. У каждого видны шанс, сумма, штраф, ❤️, ⚡ и срок. Взятое предложение гаснет навсегда, провал сжигает весь контакт. Новые приходят из более глубокого круга: грязнее, рискованнее, дороже по ❤️. Каждая сделка добавляет «засвет», он режет шансы, пока не пропустишь день. Часть предложений сама развод; Изнанка говорит это прямо. Сделка занимает вечер (правило пакета 1).

## 2. Фантазия игрока
День 3: «Толик зовёт помыть машину без номеров, 80% на +800. Мама подождёт до завтра». День 24: «Толика и Вадика нет. Гоша "знает сейф", 40%, штраф 4000, ❤️ −4. Счёт послезавтра, засвет 40». MDA: Challenge (решение дня зависит от кошелька, дня до счёта, засвета и того, что осталось в ломбарде) и Narrative (список контактов и есть дуга падения). Ожидаемая ценность любой сделки ниже смены: темка остаётся ставкой на отыгрыш, а не работой.

## 3. Данные

### 3.1. Определения (`src/game/content/contacts.ts`, числа прямо в данных, как карточки сна; тексты — i18n `CONTACT_TEXTS`)
```ts
export type ContactId = 'neighbor' | 'tolik' | 'vadik' | 'lyoha' | 'valera' | 'mentor' | 'dima' | 'gosha' | 'kirill' | 'eduard'
export interface OfferDef {
  id: string; contact: ContactId; tier: 1 | 2 | 3
  energy: number            // ⚡
  successChance: number     // p до засвета, 0…1
  rewardMin: number; rewardMax: number  // кратно CONTACT_REWARD_STEP
  fine: number              // штраф при провале, через forcedPay (недостача → МФО)
  rep: number               // ❤️, списывается всегда и первым делом (≤ 0)
  tiltFail: number          // 🔥 при провале
  heat: number              // засвет после сделки
  jail: number              // шанс «Сел» при провале, если открыт риск ареста (§4.4)
  expiry: number            // дней жизни: 0 «только сегодня», 1 «до завтра», 2
  weight?: number           // вес в пуле, по умолчанию 1
  requiresItem?: ItemId     // без вещи в статусе owned не выпадает и не выполняется
  minDebt?: number          // выпадает только при debtOf ≥ minDebt
  afterOffer?: string       // выпадает только если это предложение уже брали
  scam?: { price: number }  // развод: успеха нет, списывается price
}
```
`config.contacts.offers: readonly OfferDef[]` (через `GameConfig`, как `config.events`). Тест контента: id уникальны; `rewardMin ≤ rewardMax`, кратны шагу; у развода `successChance = 0`, `fine = 0`; EV каждого нормального предложения по §5 ≤ `CONTACT_EV_PER_ENERGY_MAX` × energy.

### 3.2. Состояние (`RunState.contacts?`, только при `contactsOn`)
```ts
contacts?: {
  offers: { id: string; reward: number; expiresDay: number }[]  // на руках; reward уже брошен
  used: string[]      // id взятых предложений: больше не выпадают
  burned: ContactId[] // контакты, сгоревшие после провала
  heat: number        // засвет 0…100
  lastDealDay?: number  // день последней не-разводной сделки
  fakeLuckUntil?: number // «прокачка удачи»: только значок в Витрине
}
```
`burnedCount(run) = used.length + число предложений сгоревших контактов, которых нет в used`. Создаётся в первом `wake` при флаге. `save/validate.ts`: копировать, только если структура валидна; неизвестные id (удалённые из контента) выкидывать.

## 4. Правила

### 4.1. Глубина круга
`depth(run)`: 1 по умолчанию; 2, если выполнено любое из `day ≥ 8`, `burnedCount ≥ 2`, `debtOf ≥ 5000`, `rep ≤ 5`; 3, если любое из `day ≥ 15`, `burnedCount ≥ 5`, `debtOf ≥ 15000`, `rep ≤ 0`. Веса ярусов по глубине `CONTACT_TIER_WEIGHTS`: глубина 1 → [1, 0, 0], 2 → [2, 3, 0], 3 → [1, 2, 4]. Вес предложения = вес его яруса × `weight`. Сползание работает само: хорошие контакты гаснут, долг растёт, ❤️ падает, и выпадают ярусы 2–3.

### 4.2. Утро: обновление (M4½ в `wake`, после энергии, до события сна)
1. `sub = createRng(deriveSeed(run.seed, run.day, CONTACT_SALT_GEN))`. Основной `ctx.rng` не трогается.
2. Выкинуть из `offers`: `expiresDay < day`; контакт в `burned`; `requiresItem` не owned; условия `minDebt` не выполнено.
3. `slots = day ≤ 7 ? CONTACT_SLOTS_WEEK1 (2) : CONTACT_SLOTS (3)`. Пока `offers.length < slots`: кандидаты = предложения, не в `used`, не на руках, контакт не сгорел, условия выполнены, вес > 0. Пусто → стоп (UI «Телефон молчит»). Иначе взвешенный выбор `sub`, `reward = STEP × sub.int(min/STEP, max/STEP)`, `expiresDay = day + expiry`. Порядок кандидатов = порядок в контенте (детерминизм).
4. `deriveSeed(seed, day, salt)` — новый экспорт `rng.ts`: `(Math.imul((seed ^ salt) >>> 0, 0x9e3779b1) + Math.imul(day, 0x85ebca6b)) >>> 0`. Соли: `CONTACT_SALT_GEN = 0xc0a7ac75`, `CONTACT_SALT_DEAL = 0x5ca1ab1e`. Без отдельного состояния в сейве: результат зависит только от сида, дня и id, перезагрузка ничего не меняет.

### 4.3. Команда `work/offer { offerId }` (вечерняя)
Проверки: `feature_disabled` (не `contactsOn`) → phase `day` → life → `no_offer` (нет на руках; новая причина в `RejectReason`, ru.test, stoplist.test) → `item_not_owned` (есть `requiresItem`, вещь не owned) → `evening_used` → `no_energy` → у развода `no_money` с `min = price` (платится из кошелька, в долг не продают).
`apply`:
1. `eveningUsed = 'shady'` (слот тот же, строка «у гаражей» подходит), ⚡ −energy, `changeRep(rep)`, предложение убрать из `offers`, id в `used`.
2. Развод: `wallet −= price`, событие `scamPaid { offerId, price }`. У `luck_boost` ставится `fakeLuckUntil = day + 3`. Больше ничего. Засвет не растёт, `lastDealDay` не ставится.
3. Иначе: `deal = createRng(deriveSeed(seed, day, CONTACT_SALT_DEAL ^ fnv1a(offerId)))`. `p = pEff(run)` (§5), успех если `deal.next() < p`. Успех: `wallet += reward`, `today.earned += reward`. Провал: `forcedPay(fine, 'shady_fine')`, `addTilt(tiltFail, 'scheme_fail')`, контакт в `burned`, бросок ареста (§4.4). Событие `schemeResolved { success, amount, fine, jailed, offerId }` (новое опциональное поле; статистика «Темок» считается как сейчас).
4. После броска: `heat = min(100, heat + def.heat)`, `lastDealDay = day`.
`work/shady` при `contactsOn` → `feature_disabled`. `SHADY_*` остаются для флага `false`.

### 4.4. Засвет и «Сел»
- Шанс на карточке и в броске — `pEff` от засвета **до** сделки.
- Ночь, N7 до удаления `eveningUsed`: если `lastDealDay !== day`, то `heat = max(0, heat − CONTACT_HEAT_DECAY_QUIET)`. В день сделки засвет не спадает.
- Риск ареста открыт, если `rep ≤ SHADY_JAIL_REP` (−10, как сейчас) **или** `heat ≥ CONTACT_HEAT_JAIL` (60). Тогда при провале `jailed = deal.next() < def.jail` → `proposeEnding('jail')`. Порядок бросков фиксирован: успех, потом арест.

## 5. Формулы и EV
- `pEff = clamp(successChance − heat × CONTACT_HEAT_PENALTY, CONTACT_P_MIN, CONTACT_P_MAX)` = clamp(p − 0.005·heat, 0.05, 0.95). Засвет 40 → −20 п.п.
- `EV₽ = pEff·R̄ − (1 − pEff)·F`, где R̄ = (min+max)/2. `EV/⚡ = EV₽ / energy`. `EVнетто = EV₽ − |rep|·V❤️`, V❤️ = 150₽ (quick-fix §3.2: +1❤️ ≈ 0.23 смены на 5-м дне и 0.08 на 20-м; середина ≈ 150₽). У развода EV = −price.
- Планка: смена 900₽/60⚡ = **15₽/⚡** (база, без повышений), маржинальная переработка 180₽/20⚡ = 9₽/⚡, старая темка 150₽/30⚡ = 5₽/⚡. Правило: `EV/⚡ ≤ CONTACT_EV_PER_ENERGY_MAX = 8` при засвете 0 (тест контента). С засветом и ❤️ сделка всегда хуже смены.

## 6. Крайние случаи
- Вещь заложили, пока предложение на руках: карточка остаётся серой («Велик в ломбарде»), команда `item_not_owned`; утром предложение выпадает. Выкупил — снова может выпасть, если не в `used`.
- Кандидатов нет (всё сожжено): слоты пустые. Ни одна глубина не генерирует новые предложения сверх контента.
- `rep` после списания ≤ −15: `family_left` предлагается как сейчас, бросок сделки всё равно идёт (порядок старой темки).
- Штраф больше кошелька: недостача через `forcedPay` в МФО, может превысить лимит, как у старой темки.
- «Ночь в казино» и пробуждение там: `work/offer` отклоняется `in_casino`, пока не выйдешь.
- Счёт сегодня и предложение «только сегодня»: порядок действий свободный, сделка до оплаты счёта разрешена.
- «Ещё неделю» (endless): контакты продолжаются, глубина 3 с дня 15, пул не пополняется.
- Карточка сна меняет ⚡ утром: генерация идёт после M4, поэтому ⚡ на карточке уже честная; предложения дороже остатка ⚡ показываются серыми с `no_energy`.
- Вырожденные стратегии. «Каждый день сделка»: засвет +10…30 без спада, p падает на 5–15 п.п. в день, ❤️ уходит в минус, смена ×0.7 (≤ 5% побед). «Только ярус 1 и мама через день»: ≈ +1 000₽ за ран, это ≤ 1 смена (§7). «Ждать хорошее предложение»: пул детерминирован сидом и днём, перезагрузка его не меняет.

## 7. Боты и ожидаемый winrate
- Хелпер `bestOffer(s, opts)`: из `offers` без разводов, где `canExecute` проходит, максимум `EV₽(pEff)`; при равенстве меньший ярус, потом порядок контента. Разводы боты не берут никогда.
- `shady` (темщик каждый день), при `contactsOn`: `leaveIfWoke`; смена; `bestOffer` любой, даже в минус; `repayAll`. Иначе как сейчас.
- `shadyCautious`, при `contactsOn`: смена; сделка, если ❤️ ≥ 4, `reserveNeeded > −2000`, есть `bestOffer` с `EV₽ > 0`, `pEff ≥ 0.5`, риск ареста закрыт; иначе мама.
- `randomStrategy` (golden): действие `work/shady` на той же позиции списка при `contactsOn` превращается в `work/offer` с `rng.pick(offers)` (если пусто — ничего, без броска). При флаге `false` список и броски не меняются.
- `honest`, `honestFormal`, `ludoman`, `casinoDaily` не трогают контакты. Генерация не касается основного RNG, поэтому их исходы по каждому сиду совпадают с флагом `false` (меняется только хэш `RunState`).

| Бот | Сейчас (economy-v1 §14.1a) | Ожидание | Коридор (тест) |
|---|---|---|---|
| Честный | 57.6% | 57.6% (исходы по сидам те же) | 55–66% |
| Темщик осторожный | 39.6% | 40–47%: ярус 1 выгоднее старой темки на ≈ +100₽ за раз, ❤️ дешевле, но всего 5 хороших сделок | ≤ честный − 8 п.п. |
| Темщик каждый день | 0% | 0–2% | ≤ 5% |
| Казино каждый день / лудоман | 5.7% / 0% | без изменений | как в пакете 1 |

Если осторожный > честный − 8: сначала ❤️ яруса 1 −1 → −2, потом `tolik_wash`/`vadik_truck` R̄ −100.

## 12. Критерии приёмки
1. `contactsOn = false`: GOLD-01 и GOLD-02 зелёные без перегенерации; `work/offer` → `feature_disabled`; `contacts` в `RunState` нет; type-check и все тесты проходят.
2. `contactsOn = true`: `work/shady` → `feature_disabled`; GOLD-03 записан и детерминирован (повтор даёт те же хэши).
3. Честный, лудоман, казино каждый день: исход по каждому из 20 сидов GOLD-03 совпадает с GOLD-02.
4. Предложения дня зависят только от (seed, day, состояние): одинаковые для двух сессий с одним сидом и одинаковыми действиями; вызовы генерации не меняют `run.rngState`.
5. День 1: ровно 2 предложения яруса 1. День 8 без долгов: 3 слота, ярус 2 возможен. Долг 15 000 на 3-й день открывает ярус 3.
6. Взятое предложение не выпадает до конца рана; после провала все предложения контакта исчезают и больше не выпадают.
7. Заложен велик: `lyoha_courier` серый с `item_not_owned`, утром исчезает, после выкупа может выпасть снова.
8. Засвет: сделка яруса 2 при heat 0 → 20; день без сделки → 0; p на карточке при heat 40 ниже базового на 20 п.п. Провал при heat ≥ 60 и ❤️ > −10 бросает арест с шансом `def.jail`.
9. Развод: списывает price, `schemeResolved` не пишется, `scamPaid` пишется, засвет не меняется, в Изнанке видна строка `honest`.
10. Тест контента: каждое нормальное предложение `EV₽ / energy ≤ 8` при heat 0; у разводов `successChance = 0`.
11. Баланс (ядро 2000 ранов, sim.mjs 20 000): честный 55–66%; осторожный темщик ≤ честный − 8 п.п.; темщик каждый день ≤ 5%; B-06c ≤ +150₽/день.
12. Логи 20 ранов осторожного темщика: доля дней с одинаковой парой «смена + то же предложение» ≤ 35% (каждое предложение одноразовое).
13. Плейтест (5 человек): ≥ 3 называют разных людей, с кем имели дело на 1-й и на 4-й неделе; ≥ 3 хотя бы раз отказались от сделки из-за засвета или ❤️; никто не называет сделки выгоднее смены.
